# IELTScope 首次建档、考试记录与目标设置设计

**状态**：用户已确认，可进入实施  
**日期**：2026-07-16  
**范围**：注册后的首次建档、考试记录录入、目标设置、诊断入口  
**不在本规格内**：四科诊断题目与评分、完整学习计划生成、兑换码核销、OCR 供应商选型

## 1. 目标

为注册学生提供一个可中断、可恢复的四步建档流程，收集后续能力诊断所需的最小信息。历史成绩只帮助形成粗略起点判断，不能替代正式四科诊断，也不能直接生成看似精确的学习计划。

免费用户可以完成建档、四科诊断和基础结果查看。兑换码只解锁完整个性化学习计划、AI 写作/口语精批额度和其他会员权益，不出现在建档流程中。

## 2. 产品原则

1. **诊断优先**：最终四科水平、目标拆解和计划以正式诊断为主。
2. **来源透明但不鉴真**：只说明记录来自 PDF 或手动填写，不判断文件真实性，也不做复杂可信度加权。
3. **PDF 是正式方向**：PDF 用于减少填写成本和保留原始参考；手动录入是首版测试和无文件时的降级路径。
4. **不阻塞建档**：文件解析失败或需要人工复核时，学生仍可继续目标设置和诊断。
5. **不制造假精度**：诊断前只给粗略起点范围，不输出精确四科方案。
6. **逐步保存**：每一步都可恢复，网络失败时保留本地草稿并显示同步状态。

## 3. 用户流程

`/onboarding` 根据学生当前进度跳转到对应步骤。各步骤使用独立 URL，便于恢复、刷新和浏览器返回：

1. `/onboarding/status`：备考情况
2. `/onboarding/records`：考试记录
3. `/onboarding/goal`：目标与时间
4. `/onboarding/review`：确认档案

提交确认后进入 `/assessment` 诊断说明页。尚未完成诊断时，工作台只显示档案摘要和“继续诊断”，不显示模拟出来的精确学习任务。

### 3.1 备考情况

学生选择：

- 有近三个月成绩
- 首次备考或暂无可参考成绩

选择只决定下一步的默认状态，不限制学生之后补充记录。

### 3.2 考试记录

- 最多 5 份记录。
- 支持 PDF 上传和手动录入。
- 支持官方 IELTS 成绩单/e-TRF、机构模考或教师报告等常见 PDF，也支持手动记录。
- 历史记录按考试日期倒序展示。
- 页面明确提示：历史成绩只作参考，最终以能力诊断为准。
- 学生可以跳过此步骤。

多份记录不做复杂综合评分、真实性判断或权重计算。系统只按日期展示，并提供一个明确标为“历史参考”的粗略起点判断；正式诊断结果统一覆盖该判断。

### 3.3 目标与时间

必填：

- 目标总分：5.5 至 9.0，间隔 0.5
- 预计考试日期：必须晚于当前日期
- 每周可学习时间：小时步进器

选填：

- 单科最低要求，可为一个或多个科目设置最低分

学生不需要提前填写四科目标。诊断完成后，由系统根据目标总分、单科硬性要求、当前水平和备考时间推算四科目标。

### 3.4 确认档案

确认页展示：

- 备考情况
- 考试记录及来源状态
- 目标总分和单科要求
- 考试日期、剩余备考周数和每周时间

所有分组均提供“修改”入口。主按钮为“确认档案，进入能力诊断”。

## 4. 界面设计

建档采用专注式全屏布局，不显示工作台侧栏。

### 桌面端

- 左侧为窄步骤导航，显示四步状态。
- 右侧为最大宽度约 720px 的主表单区域。
- 页面底部固定“上一步”和“保存并继续”。
- 顶部显示 IELTScope、当前步骤和自动保存状态。

### 移动端

- 左侧步骤导航改为顶部进度条。
- 表单、文件状态和按钮单列排列。
- 支持系统文件选择，不依赖仅桌面可用的拖放操作。

### 视觉规则

- 沿用工作台的白色、冷灰、深绿和紧凑系统字体。
- 不使用大面积营销插图或嵌套卡片。
- 文件记录使用紧凑边框列表，不做装饰性卡片墙。
- 所有按钮、状态、错误和上传进度必须有文字说明，不能只依赖颜色。

## 5. PDF 处理与数据提取

### 5.1 上传限制

- 只接受 PDF。
- 单份最大 10 MB。
- 校验扩展名、声明 MIME、实际文件头和页数。
- 计算 SHA-256，防止同一学生重复上传同一文件。
- 文件存入私有对象存储，不生成永久公开 URL。

### 5.2 解析管线

1. 文件上传并创建 `exam_document`。
2. 尝试识别常见成绩单或模考报告版式，仅用于选择字段提取规则。
3. 数字 PDF 先提取文本层。
4. 无有效文本层时调用 OCR 适配器。
5. 使用确定性规则提取考试日期、总分、听力、阅读、写作和口语。
6. 校验分数范围、0.5 分档和总分计算关系。
7. 展示原文件预览与结构化字段，要求学生确认。
8. 确认后写入 `exam_records`。

大模型可以在后续作为版式分类或异常说明的辅助工具，但不得自行补全缺失分数或绕过确定性校验。

### 5.3 处理状态

- `processing`：解析中
- `awaiting_confirmation`：等待学生确认
- `ready`：成绩字段已确认并录入
- `needs_review`：需要人工复核
- `failed`：解析失败

记录保留 `pdf` 或 `manual` 来源，方便学生回看。来源不参与正式诊断评分，也不显示“已核验”或类似真实性承诺。

### 5.4 首个实施里程碑

首个里程碑必须交付完整上传、私有存储适配器、文件校验、文本型 PDF 提取、字段确认和所有状态界面。扫描 PDF 的真实 OCR 调用通过独立供应商适配器接入；在供应商凭据和教师审核样本未提供前，进入 `needs_review` 并允许学生手动补充。

本地开发使用私有本地存储实现，生产实现保持 S3 兼容，可接 Cloudflare R2 或其他对象存储。对象存储与 OCR 供应商均不得渗透到页面组件和领域逻辑中。

## 6. 数据模型

### 6.1 `student_profiles`

新增或明确：

- `onboarding_step`
- `onboarding_completed_at`
- `weekly_minutes`

### 6.2 `exam_documents`

- `id`
- `user_id`
- `object_key`
- `original_filename`
- `content_type`
- `byte_size`
- `sha256`
- `document_kind`
- `parse_status`
- `extracted_fields` JSON
- `parser_version`
- `confirmed_at`
- `review_note`
- 时间戳

对象键、解析结果和人工备注只对文件所属学生与授权工作人员可见。

### 6.3 `exam_records`

在现有结构上增加或明确：

- `source_type`：`pdf`、`manual`
- `parse_status`
- `source_document_id`，手填记录为空
- `confirmed_by_user_at`

所有雅思分数在数据库中使用半分单位整数，避免浮点误差，例如 6.5 存为 13；契约层负责与界面分数互相转换。

### 6.4 `goals`

保存：

- 目标总分
- 预计考试日期
- 每周学习分钟数
- 单科最低要求
- 是否为当前有效目标

提交新目标时，旧目标失效但不删除，以保留后续计划历史。

## 7. 接口与模块边界

### 页面接口

- 保存或读取当前建档草稿
- 上传考试记录 PDF
- 查询解析状态
- 确认或修改提取字段
- 新增、修改或删除手填记录
- 提交完整档案

### 服务边界

- `OnboardingService`：步骤状态、目标、最终提交事务
- `ExamDocumentService`：文件归属、上传限制、状态流转
- `ExamDocumentParser`：文本提取、OCR 适配和字段抽取
- `PrivateObjectStore`：上传、短时预览、删除
- `BandScore` 契约：合法分数与半分单位转换

页面只消费类型化结果，不直接调用存储 SDK、OCR SDK 或数据库。

## 8. 安全、权限与错误处理

- 所有接口要求有效登录态，并按 `user_id` 校验资源归属。
- 学生不能构造对象键访问其他学生文件。
- PDF 预览使用短时授权地址，禁止公开目录索引。
- 上传失败、解析失败和保存失败使用不同错误文案。
- 解析超时不阻塞目标设置，状态保持为后台处理中。
- 自动保存失败时保留浏览器草稿，显示“尚未同步”，恢复网络后可重试。
- 重复 PDF 返回现有记录，不创建第二份文件。
- 最终提交在数据库事务中完成，避免目标、档案状态和考试记录部分成功。
- 恶意、损坏、超限或伪造 MIME 文件被拒绝并记录安全事件，不进入解析器。

## 9. 诊断与付费衔接

- 完成建档后进入 `/assessment`，不检查会员状态。
- 正式诊断结果覆盖历史成绩形成的粗略起点判断。
- 免费结果包含四科基础范围、主要薄弱项和建议优先级。
- 完整个性化计划、AI 精批额度和会员内容在结果页通过兑换码解锁。
- 兑换失败不能删除或隐藏免费诊断结果。

## 10. 验收测试

### 单元测试

- Band Score 合法值、半分单位转换和非法输入。
- 目标日期、每周时间、总分与单科要求校验。
- PDF、手动来源与处理状态转换。
- 多记录粗略参考逻辑不输出精确计划。
- PDF 文件头、大小、重复哈希和页数限制。

### 组件测试

- 四步导航、返回修改和自动保存状态。
- 无成绩用户跳过记录步骤。
- PDF 各解析状态与字段确认。
- PDF 与手动记录显示清晰但中性的来源标签。
- 目标总分、考试日期、学习时间和单科要求交互。

### 接口与权限测试

- 未登录请求被拒绝。
- 学生不能读取、确认或删除他人的文件。
- 重复上传返回现有记录。
- 解析失败、超时和人工复核不阻塞建档。
- 最终提交事务回滚。

### 浏览器测试

- 有 PDF 记录的四步完整流程。
- 无成绩记录的四步完整流程。
- 中途退出后恢复进度。
- 桌面和 390px 手机布局无横向溢出。
- 完成后进入诊断说明页。
- 建档期间不出现兑换码拦截，也不提前生成精确学习计划。

## 11. 完成标准

1. 学生可完成、退出并恢复四步建档。
2. PDF、手填和跳过三条路径均可用。
3. 数据来源与处理状态对学生清晰可见，但不暗示真实性核验。
4. 文件归属、私有预览和上传校验通过安全测试。
5. 建档完成后进入免费诊断，不被会员状态阻断。
6. 桌面与移动端通过系统 Chrome 视觉和交互检查。
7. 在真实 OCR 供应商尚未接入时，扫描件进入人工处理或手动补充，不阻塞诊断。
